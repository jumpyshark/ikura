# 手動撮影・画像確認

## 操作

1. 「撮影・画像を選択」で画像の一覧を開く。
2. 「レシートを撮影」でカメラを起動し、自分でシャッターを押す。撮影後は一覧に戻る。「次のレシートを撮影」で追加する。最大10枚。
3. 画像選択では、レシートと決済画面を区別する。複数選択できる。
4. 「撮影を終了して画像を確認」で初めて範囲の推定・補正を行う。
5. 各画像を確認する。範囲の調整、全体に戻す、90度回転、元の色／くっきり／白黒、元画像との比較、撮り直し、削除ができる。
6. 全画像を確認してから、1枚ずつ文字を読み取る。中止しても、この操作中は画像・確認状態・完了した読み取り結果を保持する。
7. 読み取り結果は1件ずつ保存またはスキップ。日付・店舗・金額の重複確認は従来どおり行う。最後に保存件数・スキップ件数を表示する。

## 日本語表示

アプリ内の操作・警告・取引種別は日本語。「認識信頼度○%」は廃止し、未入力項目を強調する。ReceiptLogや決済サービスの正式名称は変更しない。カメラ・写真選択・OSの権限ダイアログのボタンは端末側の言語設定に従う。iOSのアプリ言語・権限説明は日本語を指定する。

## 実装上の範囲

- 新規依存パッケージのインストールはネットワーク承認がキャンセルされたため実行できなかった。既存のexpo-image-pickerの手動カメラを使う。カメラの常時プレビューや自動シャッターは使わない。
- 画像の回転・切り取り・補正は既存のOCRネイティブモジュールへのpatch-packageパッチに含める。iOSはImageIO/UIKit/CoreImage、AndroidはBitmap/ExifInterface/ColorMatrixを使用する。
- 長辺を最大2600画素に縮小した作業画像を使い、1枚ずつ処理する。元の選択画像は書き換えない。
- 切り取り候補は、低解像度の明度画像から大きな明るい領域を探す保守的な処理。余白を追加し、不明瞭な背景や複数の領域では全体を保持する。長方形の調整であり、四隅の射影変換ではない。強い傾き、影、白い背景、複雑な背景への精度保証はない。
- スクリーンショットは全体・元の色を初期値とする。補正を強制しない。
- 元画像・確認設定は操作中に保持するが、アプリ終了からの未保存セッション復元は未実装。
- 保存対象は支出情報。バッチの確認用画像URIはDBに保存しない。生成した確認用画像だけを完了・破棄時に削除し、元画像や過去の保存済み画像は削除しない。
- 中止は後続処理と結果反映を止める。実行中のネイティブ処理は完了する場合がある。
- 同じ画像の結果へ戻る場合、編集した取引情報を保持する。画像を変更して結果を更新する場合は、未保存の編集を置き換える前に確認する。

## 検証

- TypeScript確認、24件のテスト（切り取り座標・範囲推定・既存の支出解析）、iOS/AndroidのJavaScriptバンドル生成を確認。
- ネイティブパッチを元ソースのコピーに再適用し、ファイル内容の一致を確認。
- iOS prebuild（依存インストールなし）を確認。依存バージョンとロックファイルは変更していない。
- macOS/XcodeとAndroid SDKでのネイティブコンパイル、実機での撮影・タッチ操作・メモリ使用は未検証。新しいIPA/APKが必要。
- 全プラットフォームのexportは、既存のWeb版SQLiteのwasm解決エラーで失敗した。モバイル向けの個別exportは成功。ブラウザー版の修復はこの変更に含めない。

## 実機チェック

- 3枚撮影し、撮影前の自動処理がないこと、各写真を確認できること。
- カメラをキャンセルしても撮影済み画像が消えないこと。
- 複数のレシート画像・決済スクリーンショットを選択し、初期設定の違いを確認する。
- 4つの切り取りハンドル、回転、全体に戻す、フィルター、元画像比較、削除・撮り直しを確認する。
- 確認済み画像を変更すると確認が解除されること。
- 読み取り中に中止して再開し、古い結果が上書きしないこと。
- 結果を修正して画像確認に戻り、変更せず結果に戻ると修正が残ること。
- 2件保存・1件スキップし、集計と履歴、アプリ再起動後の保存状態を確認する。
- 権限拒否・読み取れない画像・通信不可でも日本語で案内されること。
